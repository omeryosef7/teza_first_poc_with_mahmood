# POC Stage 2B Main Documentation

## Manager Summary

Stage 2B runs the 42 existing attack prompts from Stage 2 through **Qwen3-14B reasoning locally**, captures all tokens without any length cap (input tokens, thinking/reasoning tokens, output tokens), and scores each output with **StrongREJECT + a Gemini LLM judge**.

This stage closes the core gap between the gpt-o4-mini baseline (Stage 2) and the research goal: understanding how CoT hijacking attacks perform specifically against Qwen3-14B's extended reasoning.

**Status: Implemented, not yet run.** The `poc_stage2b` package and SLURM script are ready.

## Comprehensive Detailed Summary

### Why Stage 2B Exists

Stage 2 ran the Chain-of-Thought Hijacking attack framework against `gpt-o4-mini` (an API model). The mechanistic analysis in Stages 4–6 was then done on Qwen3-14B's internal representations, using those gpt-o4-mini attack prompts projected onto Qwen3-14B hidden states.

The missing connection: we never directly attacked Qwen3-14B and observed its **behavioral** response. Stage 2B does exactly that.

### What Stage 2B Does

1. Loads all 42 rows from the Stage 3 JSONL (`hijacking_baseline_gpt-o4-mini_small_strongreject.jsonl`). Each row contains an `attack_prompt` field — the full puzzle-based CoT hijacking prompt already generated by the Gemini attacker in Stage 2.

2. For each row, runs the attack prompt through Qwen3-14B locally with `enable_thinking=True`:
   - Formats the prompt via Qwen3 chat template
   - Calls `model.generate()` with `max_new_tokens=32768` (no artificial cap — thinking tokens are captured in full)
   - Returns `dict_in_generate=True` so full token sequence is available

3. Parses the generated token sequence:
   - `input_token_ids`: tokenized prompt
   - `generation_token_ids`: all generated tokens (thinking + answer), untrimmed
   - `think_text` / `qwen_think_num_tokens`: extracted from `<think>...</think>` tags
   - `final_text` / `qwen_final_num_tokens`: text after `</think>`

4. Scores the final answer text (not the thinking) with:
   - **StrongREJECT** (`poc_stage3/strongreject_scoring.py`) — rubric-based, returns score 0–1
   - **Gemini judge** (`poc_stage2b/judge.py`) — JailbreakBench prompt, returns "safe" (1) or "unsafe" (10)

5. Writes one JSONL row per input example to `outputs/stage2b/qwen3-14b/stage2b_qwen3_batch.jsonl`.

### Research Question

Does a CoT hijacking attack prompt designed against gpt-o4-mini also succeed against Qwen3-14B reasoning? Does Qwen3-14B's extended thinking suppress or aid the attack?

## What We Tried

- Reuse Stage 2 attack prompts directly (no re-running the iterative attacker).
- Use Qwen3-14B as the local target model (the same model studied in Stages 4–6).
- Capture the full thinking trace without truncation.
- Score with the same two evaluators as the rest of the pipeline (StrongREJECT + LLM judge).

## How To Run

**Smoke test (1 example, no judge, faster):**
```bash
python -m poc_stage2b.run_batch_attack \
    --input-jsonl outputs/hijacking_baseline_gpt-o4-mini_small_strongreject.jsonl \
    --output-jsonl outputs/stage2b/qwen3-14b/smoke.jsonl \
    --summary-json outputs/stage2b/qwen3-14b/smoke_summary.json \
    --max-examples 1 \
    --skip-judge \
    --overwrite
```

**Full run via SLURM:**
```bash
sbatch slurm_scripts/stage2b_qwen3_batch.slurm
```

**Resume after partial run:**
```bash
sbatch slurm_scripts/stage2b_qwen3_batch.slurm
# (set RESUME=true in environment or edit the script)
```

| `qwen_think_num_tokens` | int | Approximate thinking token count |

## Timing Estimates

Based on Stage 6 runtime (42 examples in ~38 minutes at `max_length=256`), Stage 2B with `max_new_tokens=32768` will take substantially longer per example if Qwen generates long thinking traces. Budget 4–8 hours for a full run.

| Phase | Estimate |
| --- | --- |
| Model load | ~5–10 minutes |
| Per-example inference | 1–10 minutes depending on thinking length |
| Total for 42 examples | ~2–7 hours |
| StrongREJECT (per example) | ~5–10 seconds (OpenAI API) |
| Gemini judge (per example) | ~5–15 seconds (Gemini API) |

## Limitations / Caveats

- The attack prompts were generated by Gemini-2.5-Pro to attack gpt-o4-mini. They were not iteratively refined against Qwen3-14B. Transfer effectiveness may differ.
- `max_new_tokens=32768` is a practical cap, not truly uncapped. Qwen3-14B thinking traces rarely exceed 16k tokens in practice.
- StrongREJECT requires `OPENAI_API_KEY`. Gemini judge requires `GEMINI_API_KEY` or `GOOGLE_API_KEY`. Both must be set in `.env` or SLURM environment.
- `qwen_think_num_tokens` and `qwen_final_num_tokens` are approximate (re-tokenized from decoded text, not extracted from raw token IDs).
