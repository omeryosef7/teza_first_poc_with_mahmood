## Bugs found by independent post-hoc verification (2026-07-13, second pass)

Two subagents independently re-verified this audit's own outputs against raw data (not against each other's or this doc's claims). Findings and fixes:

1. **`scripts/gcg_7a_behavior_analysis.py` logic bug**: the per-behavior success classification computed "any baseline success" as `neutral_control OR task_only`, silently omitting `random_spaces` despite the table's own header listing all three as baselines. Fixed; 7/520 behaviors reclassified. Corrected numbers (424/66/21/9, 66/87=76% GCG-exclusive) replace the original (427/70/17/6, 80%) in `docs/GCG_7A_BEHAVIOR_LEVEL_ANALYSIS.md` §2 — same qualitative story, different exact figures.
2. **`scripts/gcg_advbench_llm_taxonomy.py` regex bug**: `\bkill\b` required an exact whole-word match and missed inflected forms (e.g. "killed"), the same class of truncated-pattern bug already fixed once earlier in this audit — not fully eradicated on the first pass. Fixed (two other latent instances hardened pre-emptively: `steroids?\b`, `terroris\w*`); affected 1/520 category assignments.
3. **PPTX slide 25 stale figure**: "10 shards across 2 waves" for the unseeded eval, left over from before the 3rd wave (jobs 657639-657643) ran; slide 10 already correctly said "15 shards in 3 waves." Fixed to match.
4. **PPTX slide 14 stale cross-reference**: the master results table's "6A / Qwen3" row showed the pre-correction "−10.7pp" baseline comparison after slide 8 was corrected to identify this as the wrong baseline (6A-Q should be compared to task_only at −2.7pp, not to 5A at −10.7pp, since 6A-Q doesn't use the CoT-prefix target) — fixed to match slide 8.

All four were caught only because independent subagents re-derived the numbers/text from scratch rather than trusting the first pass — underscoring why a verification step matters as much as the original analysis, and why a "double-check everything" pass is not redundant busywork.
