## Section D — Traps

1. **Absolute-position index reused across examples of different length.** Known repeat offender in this repo: `GCG/gcg_optimizer.py:683-688` computes `refusal_dir_positions = [init_spans_rd.suffix_slice.stop - 1]` from `train_tasks[0]` and then reuses it as an **absolute** index across all tasks (default `refusal_dir_position_mode="legacy_fixed"`, `config.py:121`; reused at :837, :775-795, :808; multilayer repeat at :722-729). Fixed modes exist (`per_task_suffix`, `per_task_decision`) and `repr_positions` (:645-660) is already per-task and clean. **Boombness positions must be per-task/per-example from day one; make `legacy_fixed` unreachable for Boombness.** See memory `feedback_absolute_position_index_bug.md` — this class has hit us twice.
2. **Layer indexing off-by-one (`hidden_states[0]` is the embedding).** Two conventions coexist in our repo: `pair_common.capture_components` drops the embedding row so **block L == `hidden_states[L+1]` == `resid_post[L]`**, while `ds_common.forward_hidden_states` / `capture_target_reps` **include** the embedding as index 0. `v_bomb_*.pt` uses the block-L convention (`layers: [8..21]`). IJ's `decompose_resid` also puts embed at index 0 and strides attn/mlp as `range(1, 2L, 2)` / `range(2, 2L+1, 2)`. **Assert the convention at every boundary; record it in RUNMETA; never pass a bare layer int between modules without a named convention tag.**
3. **Multi-token words.** `carrot` / `bomb` / a 42-word codeword lexicon do not all tokenize to one token, and leading-space vs no-leading-space variants differ. A codeword occurrence is a **span**, never a point. Probes trained at `codeword_last` and interventions applied at "the codeword position" must agree on which token of the span they mean, and the taxonomy of "does this word tokenize the same across conditions?" must be audited (`tokenization_audit.py`) rather than assumed.
4. **Chat-template BOS duplication.** `apply_chat_template` already emits BOS, so re-tokenizing its output with `add_special_tokens=True` yields **two** BOS tokens and shifts every span by one. IJ handles this by always using `add_special_tokens=False` after templating (`to_toks`) and warns if BOS is then missing; `_get_before_after_instr_tok_count` explicitly strips a leading BOS from the prefix string so the tokenizer re-adds it exactly once. **Assert `input_ids.count(bos_id) == 1` in the tokenization audit for every prompt.**
5. **Silently-dropped out-of-range positions.** `GCG/gcg_optimizer.py:848-858` silently drops OOB positions; IJ `get_dominance_scores` `print`s a WARNING and `continue`s past an empty slice (so a missing span shows up as a *missing key*, not an error). Both violate plan §2.2. **Every span/position consumer must raise, and route through `FailureLedger`; an empty or OOB span is a hard failure, never a skipped row.**
6. **Left padding + batching shifts spans.** All three IJ model wrappers set `padding_side='left'`; our `AttentionKnockout` is batch-1 only and requires a 4-D mask under `attn_implementation="eager"`. Do span-indexed work batch-1 or right-padded, and assert the attention implementation before any knockout run.
7. **Fast-tokenizer requirement.** `Qwen2Model._load_tokenizer` sets `use_fast=False`, which silently disables `return_offsets_mapping` — our entire word-span strategy depends on it. Assert `tokenizer.is_fast` at load.
8. **KV cache collapses the query dimension.** Under TL, `use_past_kv_cache=True` collapses the query dim to 1 during decoding and silently corrupts absolute `dst` indices (IJ's `generate` defaults it `False` — keep it). The HF analogue: any decode-time hook that indexes an absolute query position is wrong after the first generated token — which is exactly why only the `AllPosition*` primitives are valid for generation-time necessity.
9. **`Y` memory blowup.** `L·H·T²·d·4` bytes. Fine for their `message + 20-token suffix`; catastrophic for 12-demo Doublespeak prompts. Use `hook_pattern` + targeted recomputation.
10. **Head-index semantics under GQA.** With `ungroup_grouped_query_attention=True` plus the `n_key_value_heads = n_heads` hack, head indices are **query** heads, not KV heads. Llama-3.1-8B and Qwen3-14B are both GQA — a head knockout that indexes KV heads will silently hit the wrong heads.
11. **Judge-threshold drift.** `DC/scripts/behav_judge.py` uses legacy `MAL_THRESHOLD=0.25` (do not edit); new work uses `asym_p2_judge.py` at 0.5; IJ uses 0.65/0.35 bands. **Record the threshold in every results file** and never compare ASR numbers across thresholds.
12. **Stale CLI defaults.** GCG's CLI still defaults to `Qwen/Qwen3-14B`; always pass `--model-family llama --model-name-or-path meta-llama/Llama-3.1-8B-Instruct --no-filter-cand --suffix-placement user` explicitly (`--no-filter-cand` is mandatory: `filter_cand=True` silently kills all optimization with BPE tokenizers).
13. **SLURM footguns.** Never pass `--exclude` (it nullifies `#SBATCH --nodelist`); never pass comma-lists via `--export` (they silently truncate — verify row counts even after "COMPLETED"); cap ~2 model-loading jobs per node; kill+resubmit anything PENDING > 30 min.

## Section E — Open questions for the human

1. **Do we install Matan's TransformerLens fork at all?** TL is not installed anywhere on this machine. `Y@dir` needs `hook_Y_out` from `matanbt/TransformerLens@d68e8b5`. Options: (a) isolated env with the fork, fp32, short prompts only; (b) reimplement `Y = A · X W_VO` on HF eager attention ourselves, validated against their two sanity asserts. (b) is more work but avoids fp32/no-LN-folding and the OOM ceiling, and keeps one stack. **Recommend (b); needs a decision before Phase 4.**
2. **Which `v_bomb_*.pt` is canonical for the new aligned prompt bank?** Six exist (clearharm / advbench / advbench_v2 / generated / Qwen3-14B / Phi-4-mini). All were built on the *misaligned* prompt families. Do we rebuild directions on the new skeleton-aligned bank (correct, costs a Phase-3 rerun) or reuse the existing ones (fast, but the direction may encode the demo-text confound)?
3. **How strict is the alignment gate?** We need concrete pass thresholds for §3.1: minimum content-word Jaccard, maximum |Δtokens|, maximum |Δchars| between doublespeak and benign/shuffled. Current state is 0.092 median Jaccard; a `{w}`-skeleton should give ~1.0, but the query sentence still differs. Is "identical except the word slot" the target, or "Jaccard ≥ 0.8"?
4. **Read layer per model.** Our probes select on dev (Llama band L8–21, `v_bomb` layers 8–21, refusal at L18); IJ report Llama-3.1-8B at **L14** for dominance. Do we adopt their L14 for the attention/dominance analysis while keeping our dev-selected layer for the representational Boombness score, or force one layer for both?
5. **Prompt-level Boombness definition.** §7.2 requires one number per prompt from many per-occurrence values. Mean over occurrences? Last occurrence only? Max? IJ's `topk(q)`-then-sum with `q ∈ {1.0, 0.1}` is a defensible default — is that the pre-registered choice, or do we sweep and report all?
6. **Is `MatanBT/gcg-evaluated-data` reachable?** `HF_HUB_OFFLINE=1` is set repo-wide. If we want their suffix pool as an external replication set, someone must pre-download the parquet on a networked node.
